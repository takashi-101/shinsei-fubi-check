申請書類 記載漏れ・添付漏れ確認ツール

受け付けた申請書の記載漏れ・書式の誤り・添付書類の不足を、受付の時点で下確認します。入力した申請書の内容はこのPCの外に出ず、画面を閉じると消えます。

最終の判断は職員が行います。このツールの結果は、記載漏れ・添付漏れを見つけるための下確認です。

受付の情報

申請の種類が登録されていません。「確認項目の設定」で登録するか、下の見本で試してください。

見本で試す（架空のデータ）

見本の申請の種類（3種類）と、記載漏れのある例・そろっている例を、ボタン1つで試せます。「値を入れる」は申請書の値を入れた状態に、「PDFを取り込む」は見本の申請書PDFから候補を入れる操作を試します。

申請書ファイルから候補を入れる（任意）

文字を選べるPDF（電子申請・パソコンで作った申請書）を、ここに落としてください。スキャン画像（PNG・JPEG）も読み取れます。

欄名を手がかりに値の候補を入れます。入った値は候補です。申請書と見比べて、直してから確定してください。ファイルはこのPCの中だけで読み、どこにも送りません。

      AIの接続（任意）
      
      
      取り込んだ申請書の文字から、欄名で見つからなかった値の候補をAIに出させます。AIの出力は候補として入るだけで、確定は職員が行います。AIを使わなくても、ほかの機能はすべて使えます。
      
      
      
        
      
      
      
      
        
      
          
          
          
          
        
      
        
      Ollamaは、このPCの中で動くAIです。申請書の文字はPCの外に出ません。設定の手順は「使い方・データの扱い」にあります。
      
      
      
      
      
        
      外部のAPIを使うと、申請書から取り出した文字（個人情報を含む）が外部へ送られます。所属の規程で認められている場合だけ使ってください。送る前に毎回確認が出ます。
      
        
      
          
          
          
        
      
      
      
      
      
    
      
  
      

  
  
      
    
      
      
      最終の判断は職員が行います。このツールは、記載漏れ・書式の誤り・添付書類の不足を受付の時点で見つけるための下確認に使います。
      
      
      使い方
      
      
        
        
      1. 確認項目の設定：申請の種類ごとに、欄（欄名・必須か任意か・書式）と添付書類（必須・条件付き・任意）を登録し、「この申請の種類を保存」を押します。条件付きの添付書類は「どの欄がどの値のとき必要か」を選びます。初めは「見本の設定を読み込む」で架空の見本3種類を入れると、形を確かめられます。
        2. 
        
      2. 確認作業：申請の種類を選び、申請書を見ながら値を入れ、受け取った添付書類に印を付けて「確認する」を押します。結果は「要確認」「添付不足」「確認済み」に分かれ、要確認には理由が出ます。値を直すと結果もすぐ変わります。
        3. 
        
      3. PDFから候補を入れる：文字を選べるPDF（電子申請・パソコンで作った申請書）を「申請書ファイルから候補を入れる」に落とすと、欄名を手がかりに値の候補が黄色で入ります。申請書と見比べ、「この値で確定」か「候補をすべて確定」を押します。未確定の候補は要確認として扱います。
        4. 
        
      4. 画像から読み取る：スキャンした申請書（PNG・JPEG）も落とせます。手書きの文字は読み取れないことが多く、活字でも読み違いがあります。必ず申請書と見比べてください。
        5. 
        
      5. AIで候補を補う（任意）：取り込んだあと、欄名で見つからなかった欄の候補をAIに出させます。既定はこのPCのOllamaです。設定は「確認項目の設定」の画面の下にあります。
        6. 
        
      6. 記録：「確認結果票を印刷（A4）」で、確認者・審査者の押印欄のある票を印刷します。CSV・JSONでも書き出せます。
        7. 
      
      
      
      書式の種類
      
      
        
        
      • 日付：2026/4/1、2026-04-01、令和8年4月1日、R8.4.1 などを読み、存在しない日付（2月30日など）を要確認にします。
        • 
        
      • 数字のみ：数字以外の文字を要確認にします。桁数の下限・上限を指定できます。
        • 
        
      • 郵便番号：7桁（123-4567 または 1234567）。電話番号：0で始まる10桁か11桁。
        • 
        
      • 金額：「1,000,000円」「金500,000円也」などを読みます。下限・上限を指定できます。
        • 
        
      • 選択肢：登録した選択肢のどれかであること。
        • 
        
      • 記載の有無のみ：氏名・住所など個人情報の欄に使います。値は入れず、記載があるかだけを確認します。
        • 
        
      • 全角の数字は半角とみなして確認し、その旨を補足に出します。
        • 
      
      
      
      データの扱い
      
      
        
        
      • 入力した申請書の内容は、ブラウザに保存しません。画面を閉じると消えます。書き出さずに閉じようとすると確認が出ます。
        • 
        
      • このブラウザに保存するのは、確認項目の設定と、AIの接続先（URLとモデル名）だけです。外部のAPIのキーは保存しません。
        • 
        
      • 取り込んだPDF・画像は、このPCの中で読み、どこにも送りません。
        • 
        
      • 外部のAPIを選んだときだけ、申請書から取り出した文字が外部へ送られます。送る前に毎回確認が出ます。
        • 
        
      • 書き出したファイルは、使っている人がPCに保存したものです。取り扱いは各課の規程に従ってください。
        • 
      
      
      
      Ollamaの設定（AIを使う場合）
      
      
        
        
      1. Ollamaを入れ、モデルを入れます（例：ollama pull qwen2.5:7b）。
        2. 
        
      2. ブラウザからの接続を許すため、環境変数 OLLAMA_ORIGINS を設定してOllamaを起動し直します（Windowsの例：PowerShellで setx OLLAMA_ORIGINS "*"）。
        3. 
        
      3. 「確認項目の設定」の画面の下で、接続先とモデル名を入れ、「接続を試す」を押します。
        4. 
        
      4. ネットにつながったPCでは、使い終わったら OLLAMA_ORIGINS を元に戻してください（Windowsの例：PowerShellで [Environment]::SetEnvironmentVariable("OLLAMA_ORIGINS", $null, "User") を実行し、Ollamaを起動し直す）。
